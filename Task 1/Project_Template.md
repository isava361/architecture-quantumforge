2. Рекомендация для QuantumForge

Гибрид "по умолчанию OpenAI, для чувствительного — локально":

Внешние/общекорпоративные запросы, сложный reasoning, мультимодальность требуют OpenAI GPT-5/GPT-5 mini с EU data residency (или Azure OpenAI EU Data Zones) — закрывает latency, качество и комплаенс. 

Запросы с повышенной чувствительностью (SOC 2 политики, невыпущенные ADR, PII из саппорта) требуют локальный стек: Llama 3.1 8B/70B (или Qwen/Mistral) + Text Generation Inference на существующем AWS EKS, с приватными s3-бэкендами и audit-логами. 

Не использовать YandexGPT в проде из-за привязки к РФ-региону дата-центров (риски для EU-комплаенса/санкционные риски). 

Стратегия снижения затрат:
В OpenAI задействовать cached input для длинных контекстов RAG, батч-режим для оффлайн-перегенераций. 

В локальном стеке — автоскейлинг TGI, смешанный пул моделей (8B для простых ответов, 70B по fallback), агрессивный контекст-сжатие/переписывание при retrieval.

3. Эмбеддинги: локальные Sentence-Transformers vs OpenAI Embeddings

OpenAI: text-embedding-3-large (3072-d) и text-embedding-3-small (1536-d). Цены порядка $0.13 и $0.02 за 1M токенов соответственно (см. профильные обзоры/интеграторы). Качество высокое, особенно large. 

Open-source (HF/SBERT): лидеры MTEB-рейтинга 2024–2025: Qwen3-Embedding-0.6B, embedinggemma-300m, llama-embed-nemotron, есть мультиязычные варианты.

| Критерий            | Локальные S-T (all‑MiniLM‑L6‑v2, NV-Embed-v2, gte-Qwen2, bge)                                   | OpenAI Embeddings                                |
| ------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------ |
| Скорость индексации | Быстро на GPU (1×L4), приемлемо на CPU для бэтчей                             | Очень быстро (SaaS), без инфраструктуры          |
| Качество поиска     | SOTA (по MTEB), отличная управляемость (матрешечные/редуцируемые размерности) | Стабильное, предсказуемое качество |
| Стоимость           | 0 $/токен, но свой GPU/инфра                                                  | Дешёво per 1M токенов, особенно модели `-small`         |
| Приватность         | Полный on-prem/VPC контроль                                                   | Внешний вызов API                                |

C учётом SOC 2 и того, что индексация — фоновая операция, имеет смысл локальные эмбеддинги на L4 (Qwen3-Embedding-0.6B или embedinggemma-300m) для всего массива документации.

4. Векторные БД: ChromaDB vs FAISS

| Критерий                   | FAISS                                                          | ChromaDB                                                                     |
| -------------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Скорость поиска/индексации | Эталон для ANN (IVF/HNSW/PQ, GPU поддержка)                    | Поверх ANN-библиотек, хорош для прототипирования                             |
| Внедрение/поддержка        | Лёгкая библиотека, файловое хранилище, нужен обвязочный сервис | Серверный режим/постоянное хранилище (`PersistentClient`), удобные коллекции |
| Удобство в работе          | Богатые индексы, но больше низкоуровневых настроек             | Простое API (add/query, метаданные, фильтры)                                 |
| Стоимость владения         | Дёшево (файлы/EBS), масштабирование — ваша забота              | Также локально дёшево, для кластера — DevOps трудозатраты                    |

Под текущие требования имеет смысл использовать FAISS в связке с LangChain: просто, быстро, без отдельной СУБД. Для последующего «серверного» UX можно обернуть FAISS в небольшой gRPC/HTTP-слой, Chroma удобно как dev-стор и для фич-добавок, но в проде FAISS даёт максимальную предсказуемость производительности

5. Рекомендуемая конфигурация серверов (AWS, EU-регионы)
Профили нагрузок

MVP (без GPU, всё в облаке):
Инференс: OpenAI.
Эмбеддинги: OpenAI text-embedding-3-small (для раннего мвп можно использовать embedinggemma-300m).
Узел: c7a.2xlarge (8 vCPU, 16–32 GB RAM) для API+retriever. Дешево, быстро запустить.

Гибрид (реком.): локальные эмбеддинги + облачная LLM
Узел для эмбеддингов: g6.xlarge (1×NVIDIA L4 24 GB, 4 vCPU, ~32 GB RAM). Хорош для NV-Embed-v2/gte-Qwen2 и скоростной (ре)индексации. 
Узел(ы) рантайма RAG: c7a.2xlarge/4xlarge (пара подов в EKS).
Хранилище: EBS gp3 под том FAISS (~50–200 GB + рост).
Генерация: GPT-5/mini  по маршрутизации.

Полностью локально (закрытые наборы):
Генерация: Llama 3.1-8B-Instruct (AWQ/gguf-quant) в Triton/Text-Gen Server. 1×L4 24 GB ок, 70B потребует A100/H100 (дорого, избыточно).

6. Итоговые рекомендации для QuantumForge

Retriever: LangChain + FAISS

Эмбеддинги: локально Qwen3-Embedding-0.6B, пилот/легаси — text-embedding-3-small. 

LLM-провайдер: по умолчанию GPT-5/mini, Llama 3.1-8B как офлайн-fallback. 

Инфра: EKS (узлы CPU для API и RAG-оркестратора, GPU-узел g6.xlarge для эмбеддингов), ECR, IaC (Terraform/Helm), логирование «не знаю» ответов. 

Процессы качества и улучшений:

Feedback-петля «Я не знаю» - Confluence backlog. Темы без ответов автоматически создают тикеты с приоритетом и владельцем (CODEOWNERS/ADR-owner).

RAG-оценки по набору golden-queries (Dev/Support/PM/Onboarding) + метрики answer faithfulness.

Контроль устаревания: просроченные документы (по ADR/релиз-тегам) — в приоритизацию, бот помечает ответы как «возможна устаревшая версия».

Дедупликация: офлайн кластеризация эмбеддингов для поиска дубликатов/версий.

Версионирование индекса: snapshot FAISS + метаданные коммитов, rebuild ночами/по релиз-триггерам.

Почему это окупится:

Сокращаем TTS с часов до минут, менее опытные инженеры перестанут «рыть» по Confluence/MD.

Реже эскалируем к тимлидам/старшим (автоматизация FAQ).

Улучшаем соответствие аудитам: трассируем источники, закрываем пробелы целенаправленно.
